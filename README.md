# ETCG Supplementary Materials

Supplementary data and scripts for:

> **LLM-Based Exploratory Testing Charter Generation: An Ablation Study of Prompt Structure**
> Arbaz Surti
> *Automated Software Engineering* (Springer) — Special Issue on Automated, Verifiable, and
> Generative Approaches to Software Engineering. Under review (major revision).

## Replication

### Requirements

- Python 3.9+
- `pip install openai requests python-dotenv numpy scipy matplotlib pandas statsmodels openpyxl`
- An [OpenRouter](https://openrouter.ai) API key (generation and scoring only; the analysis
  runs offline)

### Setup

```bash
git clone https://github.com/arbaz-surti/etcg-supplementary
cd etcg-supplementary
cp .env.template .env
# Add your OpenRouter API key to .env
pip install openai requests python-dotenv numpy scipy matplotlib pandas statsmodels openpyxl
```

### Regenerate every number in the paper (offline, no API key)

`scripts/analysis.py` computes every quantity reported in the manuscript from the frozen
scoring files. Nothing in the manuscript is typed by hand: prose cites generated LaTeX
macros, and tables are `\input` from generated files.

```bash
python scripts/analysis.py
# Reads:   data/etcg-scores.json                    (the authoritative 3-condition corpus)
#          data/etcg-scores.json.pre-splitfix-backup (to report what the splitter repair changed)
#          data/etcg-scores-{gemini,sonnet}.json     (cross-model judges)
#          data/multimodel/<model>/scores.json       (multi-model generalisation)
#          data/generation-instrumentation.json      (cost and latency)
#          the two human raters' scoring sheets
# Outputs: results/results.json, results/macros.tex, results/table-*.tex,
#          results/TRACEABILITY.md, and every figure
```

Useful flags:

```bash
python scripts/analysis.py --no-figures
python scripts/analysis.py --audit-tex path/to/main.tex   # flag any hand-typed number in the manuscript
```

The script validates the design before computing anything and aborts if the corpus is not
fully crossed (25 specifications × 3 conditions × 5 charters, no scoring errors).

### Regenerate the corpus from scratch (requires an API key)

```bash
python scripts/etcg_tool.py               # -> data/etcg-results.json
python scripts/etcg_intermediate_tool.py  # -> data/etcg-intermediate-results.json
python scripts/etcg_baseline_tool.py      # -> data/etcg-baseline-results.json
python scripts/etcg_score.py              # -> data/etcg-scores.json
python scripts/judge_score.py             # -> data/etcg-scores-{gemini,sonnet}.json
python scripts/multimodel_generate.py && python scripts/multimodel_score.py
python scripts/instrument_generation.py   # -> data/generation-instrumentation.json
```

`generate_figures-RETIRED.py` is retired: it reads the old two-condition file and would overwrite
the current figures. Use `analysis.py` (or `figures.py`), which render figures from the same
values they put in the tables.

## Evaluation Design

| Parameter | Value |
|-----------|-------|
| Specifications | 25 (SPEC-01–25); 18 sparse description-only tickets, 7 structured |
| Domains | Restaurant Technology, Healthcare, Logistics |
| Conditions | ETCG (role + guidance + JSON schema), Intermediate (role + guidance, no schema), Baseline (unstructured) |
| Charters | 375 total — 125 per condition (5 per spec × 25 specs) |
| Rubric dimensions | Specificity, Testability, Risk Coverage, Clarity, Actionability |
| Scoring scale | 1–3 per dimension (max 15 per charter) |
| Primary scorer | GPT-4o at temperature 0 |
| Cross-model judges | Gemini 2.5 Pro and Claude Sonnet 4.5 rescore the full frozen corpus |
| Multi-model generation | the 3 conditions re-run on Claude Sonnet 4.5, Gemini 2.5 Pro, Llama 3.3 70B |
| Unit of analysis | **Specification (n = 25)** — charters within a specification are clustered |
| Human IRR | rater 1: 50 charters / 250 ratings (ETCG + Baseline); rater 2: 75 charters / 375 ratings (all three conditions); 50-charter overlap scored by both |

## Key Results

All values below are emitted by `scripts/analysis.py`; see `results/TRACEABILITY.md`
for the full index.

### RQ1 — overall quality by condition (specification level, n = 25)

| Condition | Mean | 95% CI | SD (spec) | SD (charter) | At ceiling |
|-----------|------|--------|-----------|--------------|------------|
| ETCG | 95.47% | [93.69, 97.24] | 4.30% | 10.07% | 101/125 (81%) |
| Intermediate | 95.78% | [93.75, 97.82] | 4.93% | 8.24% | 94/125 (75%) |
| Baseline | 94.18% | [91.75, 96.61] | 5.89% | 10.10% | 92/125 (74%) |

Pairwise contrasts use a paired Wilcoxon signed-rank test on 25 specification means;
the mixed-effects column is from a random-intercept model.

| Contrast | Difference | Signed-rank *p* | Mixed model *p* |
|---|---|---|---|
| ETCG vs Baseline (full framework) | +1.28 pp | 0.380 | 0.268 |
| Intermediate vs Baseline (role + guidance) | +1.60 pp | 0.261 | 0.167 |
| ETCG vs Intermediate (output schema) | −0.32 pp | 0.732 | 0.784 |

**No pairwise contrast reaches significance.** The headline result is a null: the full
framework is not distinguishable from an unstructured prompt at the correct unit of analysis.
The ablation finding is that role framing and explicit guidance carry whatever small point
difference exists; the JSON output schema adds nothing to the mean (its value is
machine-readability, not quality). Intraclass correlation by specification = 0.074.

> **Provenance note.** `data/etcg-scores.json.pre-splitfix-backup` is retained solely to
> regenerate the manuscript's historical splitter-repair disclosure. Current results always
> come from the corrected authoritative corpus; `analysis.py` recomputes both states rather
> than preserving result values in prose.

### RQ2 — per-dimension decomposition (exploratory)

15 dimension-level contrasts; 2 reach *p* < 0.05 before correction, **0 survive Holm–Bonferroni**.
RQ2 is reported as an exploratory decomposition of RQ1, not as confirmatory tests. No
dimension-level result should be read as confirmed.

### RQ3 — inter-rater reliability

| Pairing | Exact | Within one | Two-point | Gwet's AC2 |
|---|---|---|---|---|
| Automated vs rater 1 (250 ratings) | 65.6% | 97.2% | 7 | 0.733 |
| Automated vs rater 2 (375 ratings, all conditions) | 72.3% | 99.7% | 1 | 0.799 |
| Rater 1 vs rater 2 (50-charter overlap) | 66.0% | 97.6% | 6 | 0.720 |

Gwet's AC2 is the primary reliability statistic. The generated reliability tables also report
Krippendorff's ordinal alpha, exact agreement, within-one agreement, and every two-point
disagreement so readers can inspect the ceiling-sensitive measures rather than treating one
coefficient as definitive.

### RQ4 — specification richness

On the 7 structured specifications (SPEC-19–25) ETCG averages 99.05% (specification-level
SD 2.52%); on the 18 sparse specifications it averages 94.07% (SD 4.07%). The structured-minus-
sparse contrast is +4.98 pp (*p* = 0.014 after Holm adjustment across the three condition-wise
tests). The structured group is small and confounded with domain and authorship, so this is
reported as preliminary.

### Cross-model judges

The full frozen corpus was rescored by Gemini 2.5 Pro and Claude Sonnet 4.5 under an identical
rubric prompt. ETCG--Baseline is +0.11 pp under Gemini and −0.37 pp under Sonnet; neither
contrast is significant. The role-and-guidance and schema contrasts are judge-sensitive, so
the package reports every contrast rather than treating one judge as a replication. GPT-4o is
more lenient overall by +9.34 pp versus Gemini and +14.12 pp versus Sonnet.

### Multi-model generation

The three conditions were re-run on Claude Sonnet 4.5, Gemini 2.5 Pro, and Llama 3.3 70B, each
scored by the fixed GPT-4o judge. Role framing and guidance raise the mean on all 4/4 generators;
the schema contrast is non-significant on all four and its sign differs across generators. A
framework advantage over the unstructured prompt is significant only under Llama 3.3 70B
(+3.36 pp, *p* = 0.004), the only open-weight model tested.
